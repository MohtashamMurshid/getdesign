For a visual run, bring your own Daytona and OpenAI keys. V1 has no getdesign run billing. You pay Daytona for browser capture and OpenAI for model usage. Run duration and provider costs vary by site.

<Tabs>
  <TabItem label="Web">
    Open the [dashboard](https://dashboard.getdesign.app), sign in, and save both provider keys in Account. Then paste a URL to generate a `design.md`.
  </TabItem>
  <TabItem label="API">
    ```bash
    curl "https://api.getdesign.app/v1/design?url=https://stripe.com" \
      -H "Authorization: Bearer $WORKOS_ACCESS_TOKEN" \
      -H "x-daytona-api-key: $DAYTONA_API_KEY" \
      -H "x-openai-api-key: $OPENAI_API_KEY" \
      -H "Accept: text/markdown" \
      -o stripe.design.md
    ```
    Send a WorkOS access token plus the provider headers over HTTPS. There is no getdesign API key. See the [API surface](/surfaces/api/) for JSON and progress events.
  </TabItem>
  <TabItem label="CLI">
    ```bash
    bunx @getdesign/cli https://stripe.com
    bunx @getdesign/cli https://stripe.com --out stripe.design.md
    ```
    Requires Bun, with `DAYTONA_API_KEY` and `OPENAI_API_KEY` set in your shell. No WorkOS token is needed. Default output is `./getdesign-runs/<slug>/design.md`; there is no interactive REPL.
  </TabItem>
  <TabItem label="SDK">
    ```bash
    bun add @getdesign/sdk
    ```
    ```ts
    import { getDesign, streamDesign } from "@getdesign/sdk";

    const options = {
      credentials: {
        daytonaApiKey: process.env.DAYTONA_API_KEY,
        openaiApiKey: process.env.OPENAI_API_KEY,
      },
    };
    const result = await getDesign("https://stripe.com", options);
    console.log(result.markdown);

    // Alternative: run with progress events instead.
    for await (const event of streamDesign("https://stripe.com", options)) {
      if (event.type === "progress") console.log(event.event);
      if (event.type === "result") console.log(event.result.markdown);
      if (event.type === "error") throw new Error(event.error.error);
    }
    ```
    Run either example on a Bun server. Each call starts a separate provider-funded run. The SDK executes locally, not through the hosted API, and does not need a WorkOS token. It is not a browser or edge-runtime client.
  </TabItem>
